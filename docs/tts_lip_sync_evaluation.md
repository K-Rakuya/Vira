# State-of-the-Art TTS & 3D VRM Lip-Sync Research Report for Vira (Nov 2026)

## 1. System Constraints & Hardware Profile
* **Target Hardware:** NVIDIA RTX 4060 Laptop (8GB VRAM total).
* **VRAM Bottleneck:** Local LLM (`llama-server` running Gemma-26B / Qwen-2.5) consumes ~5.8GB VRAM. With OS desktop rendering and CUDA context overhead, **only < 1.8GB VRAM is free**.
* **Core Rule for TTS:** **TTS must run on CPU (0 MB VRAM) or consume < 800MB VRAM** to guarantee zero out-of-memory (OOM) crashes and avoid CUDA context swapping with the LLM.
* **Target Latency:** Time-to-First-Audio (TTFA) < 150ms.
* **Target CPU Efficiency:** Real-Time Factor (RTF) < 0.3 on modern laptop CPUs (AMD Ryzen 7 / Intel Core i7).
* **Audio Clock & Streaming:** 24kHz / 48kHz PCM chunk streaming into `vira-voice` `PlaybackEngine` lock-free ring buffer (`rtrb`).
* **3D Lip-Sync:** 60Hz synchronized blendshape weights (`aa`, `ih`, `ou`, `ee`, `oh`) locked to `MasterAudioClock`.

## 3. Deep-Dive: Candidate Evaluations

### A. Kokoro (Kokoro-82M, Kokoro ONNX, v0_19, v1.0)
* **Architecture:** Distilled variant of StyleTTS2 (~82M parameters). Eliminates diffusion steps in favor of single-pass feedforward style injection and linear duration prediction.
* **Performance:** Single-thread/multi-thread CPU performance is extraordinary. RTF is 0.15–0.22 on x86_64 laptop CPUs. Memory footprint in ONNX INT8 is under 90MB RAM.
* **Multilingual Status:**
  - **English:** Tier 1. Outstanding natural timbre (`af_heart`, `af_sarah`, `am_adam`, `am_fenrir`).
  - **Japanese:** Tier 1 supported via `misaki[ja]` / OpenJTalk phonetic mapping (`jf_alpha`, `jm_kumo`).
  - **Vietnamese:** Upstream official v1.0 does not include Vietnamese voice embeddings. Community models (`Kokoro-Vietnamese` + `vig2p`) exist, but require custom ONNX packaging.
* **Viseme Alignment:** Kokoro produces 24kHz audio. It does not output raw viseme packets by default, but its linear duration predictor or Vira's native `vira-voice::phoneme_aligner` can map phoneme spans into 60Hz `TimedViseme` frames.

### B. Piper TTS (VITS-based ONNX)
* **Architecture:** VITS model trained with adversarial losses, conditioned on phonemes generated by `espeak-ng` or language-specific lexicons.
* **Performance:** Ultra-lightweight and fastest in the industry. RTF is **0.03–0.08** on CPU. Audio begins emitting in **< 45ms**.
* **Multilingual Status:**
  - **Vietnamese:** Excellent official community support: `vi_VN-vais1000-medium` (CC BY 4.0 license, clean female voice), `vi_VN-vivos-x_low`, `vi_VN-25hours_single-low`.
  - **English & Japanese:** Fully covered (`en_US-lessac`, `ja_JP-hi_fi_captain`).
* **Viseme Alignment:** Because VITS explicitly predicts durations for each phoneme symbol during inference, phone boundary extraction is deterministic and exact.

### C. Edge-TTS (Local / Cloud Hybrid)
* **Architecture:** Reverse-engineered WebSocket stream to Microsoft Cognitive Speech platform.
* **Advantages:** 
  - Zero local VRAM, zero CPU usage.
  - State-of-the-art Vietnamese voices (`vi-VN-HoaiMyNeural`, `vi-VN-NamMinhNeural`), English (`en-US-JennyNeural`), and Japanese (`ja-JP-NanamiNeural`).
  - **Streams `WordBoundary` and Azure SAPI Viseme events directly** over the WebSocket alongside audio chunks!
* **Trade-off:** Requires internet connectivity and has a ~180–280ms network round-trip TTFA.

## 4. 3D Lip-Sync & Viseme Alignment Architecture for Vira

Vira already has an elegant synchronization architecture:
1. **Domain:** `VisemeWeights` in `crates/vira-domain/src/viseme.rs` holds 5 VRM vowel blendshapes: `aa`, `ih`, `ou`, `ee`, `oh`.
2. **Audio Clock:** `MasterAudioClock` in `crates/vira-voice/src/clock.rs` tracks exact sample playback via `cpal`.
3. **Tick Loop:** In `crates/vira-tauri/src/lib.rs`, a 60Hz thread samples visemes at `now_ms = clock.current_time_ms()` and emits `viseme_tick` IPC events.
4. **VRM Animator:** `frontend/src/stage/lip-sync.ts` smoothly lerps expressions with exponential smoothing ($k = 1 - e^{-32\cdot dt}$).

### Phoneme-to-Viseme Mapping Strategy:
For English, Vietnamese, and Japanese, phonemes map into the 5 VRM blendshapes:
* **`aa` (Open jaw):** English `/ɑ/`, `/æ/`, `/ʌ/`; Vietnamese `a`, `ă`, `â`, `ả`, `á`; Japanese `あ`.
* **`ih` (Spread lips):** English `/i/`, `/ɪ/`, `/j/`; Vietnamese `i`, `y`, `ê`; Japanese `い`.
* **`ou` (Pursed lips):** English `/u/`, `/ʊ/`, `/w/`; Vietnamese `u`, `ư`, `ô`; Japanese `う`.
* **`ee` (Wide open/half-spread):** English `/ɛ/`, `/eɪ/`; Vietnamese `e`, `è`, `é`; Japanese `え`.
* **`oh` (Rounded jaw):** English `/ɔ/`, `/oʊ/`; Vietnamese `o`, `ơ`, `ọ`; Japanese `お`.
* **Mouth closed (Rest / Bilabials):** `/m/`, `/p/`, `/b/`, punctuation pauses `.` `,` `...` -> `VisemeWeights::zero()`.

Vira's G2P engine in `crates/vira-voice/src/phoneme_aligner.rs` already contains native Vietnamese syllable decomposition (`vietnamese_word_to_phonemes`) and English CMU lexicon lookup!

## 5. Architectural Recommendations & Actionable Roadmap

### Recommended Architecture: Multi-Backend Hybrid
To maximize quality, reliability, and multilingual coverage without blowing the 8GB VRAM budget:

```
                                  +------------------------------------+
                                  | LLM Output (Streaming Sentences)   |
                                  +-----------------+------------------+
                                                    |
                                                    v
                                  +------------------------------------+
                                  |     Vira TtsPort Coordinator       |
                                  +-----------------+------------------+
                                                    |
                         +--------------------------+--------------------------+
                         |                                                     |
                         v                                                     v
          [Online / High Fidelity Mode]                           [Offline / Low Latency Mode]
          +-------------------------------+                       +-------------------------------+
          | Edge-TTS Client (WebSocket)   |                       | Sherpa-ONNX / Piper Engine    |
          | - Zero VRAM, Zero CPU         |                       | - 0 MB VRAM (CPU ONNX)        |
          | - Vi: HoaiMy, En: Jenny       |                       | - Vi: vi_VN-vais1000-medium   |
          | - Streams Viseme/Word bounds  |                       | - En/Ja: Kokoro-82M ONNX      |
          | - Auto-fallback on disconnect |                       | - RTF < 0.15, TTFA < 60ms     |
          +---------------+---------------+                       +---------------+---------------+
                          |                                                       |
                          +--------------------------+----------------------------+
                                                     |
                                                     v
                                  +------------------------------------+
                                  | Audio Resampler (24k/48k sinc)     |
                                  | -> PlaybackEngine Ring Buffer      |
                                  | Aligned 60Hz TimedViseme Timeline  |
                                  | -> MasterAudioClock Sync           |
                                  +------------------------------------+
```

### Actionable Steps for Implementation:
1. **Short-Term (Day 1 - Quick Win):**
   - Implement an async `EdgeTtsAdapter` in `crates/vira-infer` implementing `TtsPort`.
   - Supports crystal-clear Vietnamese (`vi-VN-HoaiMyNeural`), English, and Japanese with native `WordBoundary` timestamps and zero compute footprint.
   - Wire existing `KokoroTtsAdapter` in `crates/vira-infer` to fall back to `VirtualFallback` or local HTTP if offline.
2. **Medium-Term (Robust Offline Engine via `sherpa-onnx`):**
   - Add `sherpa-onnx` (or direct `ort`) feature to `crates/vira-infer`.
   - Download ONNX model weights into `~/.local/share/vira/models/`:
     * Vietnamese: `vi_VN-vais1000-medium.onnx` (~40MB).
     * English & Japanese: `kokoro-multi-lang-v1_0.onnx` (~88MB INT8) + `voices.bin`.
   - In `KokoroTtsAdapter::stream_synthesize`, run CPU inference yielding 24kHz audio chunks and aligned visemes directly into the `TtsStreamEvent` sender.
3. **Playback & Clock Integration:**
   - Both engines emit into `vira_tauri::commands::process_speakable_sentence`, which already resamples via Polyphase Kaiser-windowed sinc filter to 48kHz, pushes audio to `PlaybackEngine`, and enqueues `TimedViseme` frames to `active_visemes` for 60Hz 3D VRM lip-sync.
